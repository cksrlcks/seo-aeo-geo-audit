# 개선 후보 (v1.2.0 실사용 점검에서 나온 것)

2026-11-18, 플러그인 v1.2.0 을 설치해 uxis.co.kr · banyantreebusan.com 을 스킬 절차 그대로 돌린 결과에서 나온 후보다.
판단 평가(6단계)는 이전 평가를 모르는 새 에이전트에게 맡겼다.

- 측정 점수(종합 · SEO · AEO · GEO)는 이전 실행과 같게 나왔다.
- 판단 점수는 실행마다 크게 흔들렸다. 아래 표 참고.

| 사이트 | 항목 | 1차(같은 세션) | 2차(설치본, 새 평가자) |
|---|---|---|---|
| 유시스 | E-E-A-T | 51 | 61 |
| 유시스 | AI 플랫폼 평균 | 61 | 69 |
| 반얀트리 | 브랜드 언급 | 73 | 61 |
| 반얀트리 | E-E-A-T | 47 | 45 |

결과 파일: `d:\project\seo-audit-results\plugin-run\` (점검 JSON, review JSON, HTML · PDF)

## 우선순위

먼저 할 것은 1 · 2 · 5 다. 1 · 2 는 문서만 고치면 되고, 5 는 실제 오류다.

> **2026-11-19 처리**: 1 ~ 7 반영. 아래 "그 밖에 나온 것" 은 남겨 둠.
> - 5 는 Node 26.12.1 에서 재현되지 않았다(8회 모두 종료 코드 0). 추정 원인대로 `quit()`(출력 비우고 한 틱 뒤 종료)으로 바꿨다. 재현 환경이 생기면 다시 확인한다.
> - 6 은 원본 HTML 에 `1899. 3399` 가 있어 정규식 누락이 맞았다. 대표번호 구분자를 `\s*[-.]\s*` 로 넓혔다(공백만은 연도 나열 오탐 때문에 제외).
> - 3 · 4 · 6 은 반얀트리 실행으로 확인: 나무위키 '반얀트리 해운대 부산' 재조회 성공, YouTube 채널 1 · 영상 15, contact-info 통과.
> - `brand.items` 의 platform 이름이 짧아졌다("위키", "커뮤니티"). 예전 형식 review.json 은 render.mjs 검사에서 막힌다.

### 1. 판단 점수에 세부 배점 단계 넣기

**문제**: `reference/ai-review.md` 의 여러 칸이 "있음 = 만점"만 정해 두었다. 그래서 부분 점수는 평가자 마음대로 준다.

- 대상 칸
  - 네이버: 정보 영역 5, 뉴스 5, 블로그 · 카페 5
  - YouTube: 공식 채널 7, 제3자 영상 8
  - LinkedIn: 페이지 5, 활동 5
  - AI 플랫폼: 내용 구조 30, 출처 · 엔티티 30 (하위 배점이 아예 없다)
- 실제 사례
  - 유시스 네이버 블로그 · 카페에 제3자 글이 2건 있었다. 1차 평가는 3점, 2차는 2점을 줬다.
  - Copilot 의 "명확한 제목 · 메타"는 측정 항목이 통과라 거의 만점이 된다.

**수정안**
- 건수 단계를 정한다. 예: 0건 0점 / 1건 2점 / 여러 건(3건 이상) 5점.
- 플랫폼의 내용 구조 30 · 출처 엔티티 30 은 하위 항목별로 쪼갠다. 측정 항목(checks[] id)에 묶을 수 있는 것은 묶는다.

**고칠 파일**: `reference/ai-review.md`

### 2. 동명 실체 · 운영 주체 규칙 넣기

**문제**
- 유시스: 네이버 '(주)유시스 · 기본정보' 패널이 다른 회사였다(인천 송도, 대표 김희애, 음향기기 제조). 헤딩만 보고 세면 정보 영역 5점을 받는다.
- 유시스: 이코노미사이언스 기사(2026-09)에 "박종석 유시스 대표"가 나온다. 실제 대표는 박종덕이라 같은 회사인지 확정할 수 없었다.
- 반얀트리: 사이트 운영자는 반얀 그룹이 아니라 분양 시행사 루펜티스㈜다. 운영 주체를 확인하는 단계가 없어 오해하기 쉽다.
- 반얀트리: 네이버 블로그 상위 글은 대부분 회원권 영업 글이다. "영업 · 광고 글 제외" 규칙은 커뮤니티 칸에만 있고, 네이버 블로그 · 카페 칸에는 없다.
- 같은 기사가 "네이버 뉴스 5"와 "뉴스 · 업계 매체 10"에 이중으로 걸린다.

**수정안**: ai-review.md 공통 규칙에 아래를 넣는다.
- 평가 전에 사이트 운영 주체(하단 사업자 정보 · 문의 페이지)를 먼저 확인하고, E-E-A-T 근거에 적는다.
- 같은 실체로 확정하지 못한 결과는 세지 않는다. found 에 "같은 실체 확인 안 됨"과 이유를 적는다.
- 정보 패널 · 지식백과가 다른 실체면 0점으로 두고, 혼동 위험을 플랫폼 gaps 에 적는다.
- "영업 · 광고 · 채용 글 제외"를 네이버 블로그 · 카페 칸에도 적용한다.
- 같은 기사를 두 칸에서 세도 되는지 정한다(권장: 두 칸 모두 인정하되, 네이버 칸은 네이버 노출 여부만 본다).
- "검색했지만 없음"과 "확인 불가(도구 한계)"를 found 문구에서 구분한다.

**고칠 파일**: `reference/ai-review.md`

### 3. 나무위키 문서명이 다르면 놓침

**문제**: 반얀트리는 `brand.search.namu` 가 '반얀트리 부산 해운대'로 열려 404 였다. 실제 문서명은 '반얀트리 해운대 부산'이고, 네이버 통합검색 결과에는 그 링크가 있었다.

**수정안**
- `audit.mjs` 에서 네이버 total 결과에 `namu.wiki/w/` 링크가 있으면 그 주소로 한 번 더 연다.
- `search.namu` 에 실제로 확인한 문서명을 남긴다.

**고칠 파일**: `scripts/audit.mjs` (`browse` · `search.namu` 부분), `reference/ai-review.md`

### 4. YouTube 를 사실상 확인 못 함

**문제**
- 기준표의 확인 방법은 `site:youtube.com` 웹 검색이다.
- 이 환경의 WebSearch 는 미국 전용이라 한국어 결과가 약했다. YouTube 결과는 거의 나오지 않았다.
- WebFetch 로 연 YouTube 페이지는 본문이 잘렸다.
- 그래서 제3자 영상 8점은 늘 0점이 될 수 있다.

**수정안**: 네이버처럼 `browse()` 로 `https://www.youtube.com/results?search_query=<브랜드>` 화면을 기록해 `brand.search.youtube` 에 남긴다. 채널 · 영상 제목과 채널명을 추린다.

**고칠 파일**: `scripts/audit.mjs`, `reference/ai-review.md`, `scripts/report.mjs` (자동 조회 표에 행 추가)

### 5. `--detect` 가 비정상 종료 (Windows, 인증서 체인 불완전 사이트)

**재현**
```bash
node audit.mjs https://uxis.co.kr --detect ; echo $?   # 127
```

**증상**
- 결과 JSON 은 정상으로 출력된다.
- 그런데 끝에 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 76` 이 찍히고 종료 코드가 127 이다.
- 본 점검(`--detect` 없이)은 종료 코드 0 이다.
- v1.1.1 에도 같은 코드가 있어 원래 있던 문제다.

**추정 원인**
- TLS 재시도로 `--use-system-ca` 자식 프로세스가 뜬다.
- 그 자식이 감지 직후 `process.exit(0)` (audit.mjs 270행 근처)를 부르면서, fetch keep-alive 소켓이 닫히는 중에 종료된다.

**수정안 후보**
- `process.exitCode = 0` 으로 두고 자연 종료되게 흐름을 바꾼다.
- 또는 출력 flush 콜백 안에서 종료한다.
- 고친 뒤 유시스로 종료 코드가 0 인지 확인한다.

### 6. 대표번호 형식 일부를 못 찾음 (확인 필요)

**문제**
- 반얀트리 평가자가 하단 전화가 '1899. 3399'(점과 공백)로 적혀 있다고 보고했다. 점검은 `contact-info` 를 실패로 판정했다.
- `audit.mjs` 의 전화 정규식(825행 근처)은 3단 번호만 구분자 `[-.\s]` 를 허용한다. `1[5-9]xx` 대표번호는 하이픈(`1899-3399`)만 인정해서 `1899.3399`, `1899. 3399` 를 놓친다.
- 다만 그 번호가 원본 HTML 에 있는지, JS 로 그려지는지는 아직 확인하지 않았다. 원본에 없으면 점검 판정은 맞다.

**수정안**
- 원본 HTML 에 그 번호가 있는지 먼저 확인한다.
- 있으면 대표번호 구분자를 `[-.\s]+` 로 넓히고 `reference/checks.md` 에 적는다.

### 7. render.mjs 검증이 느슨함

**문제**
- HTML · PDF 쪽수를 따로 세지 않는다. 그래서 SKILL 5단계의 "쪽수 같은지"를 render 단계에서는 확인할 수 없다.
- review.json 검사에서 빠진 것이 있다.
  - 플랫폼 6개의 이름 · 순서
  - 브랜드 6개 항목의 이름 · 순서 · weight
  - gaps · fix 유무
- `url` 이 선택 항목인지 문서에 없다.

**수정안**
- render.mjs 가 PDF 쪽수를 세어 HTML 쪽수와 비교해 출력한다. audit.mjs 의 countPages 를 재사용한다.
- 플랫폼 · 브랜드 항목 목록을 ai-review.md 와 같은 상수로 두고 검사한다.
- ai-review.md 에 필수 · 선택 필드를 표로 적는다.

## 그 밖에 나온 것 (낮은 우선순위)

- **확인 수단이 없는 항목이 있다.** Gemini 의 Google 비즈니스 프로필, Copilot 의 Bing 색인, 네이버 플레이스가 그렇다. 확인 방법을 기준표에 적거나, 해당 기준을 빼거나, 브라우저 기록 대상에 넣는다(네이버 지도 · 플레이스 탭).
- **페이지를 읽는 방법이 정해져 있지 않다.** E-E-A-T 근거 페이지를 읽을 때 평가자마다 WebFetch, curl, 렌더링을 섞어 썼다. 방법을 정해 두면 재현성이 오른다.
- **비슷한 이름의 영업 도메인을 반영할 칸이 없다.** 반얀트리는 banyantreebusan.shop, banyantreehaeundae-busan.com, wixsite 영업 도메인이 네이버 상위에 함께 나온다. JSON-LD 로고도 다른 도메인(http)을 가리킨다. 엔티티 혼동 위험을 적을 칸이 기준표에 없다.
- **분양 · 회원 모집 기사를 뉴스로 셀지 기준이 없다.**
- **부록 행이 길어져 쪽수가 늘었다.** "브랜드 조회" 행이 길어지면서 유시스 보고서가 22쪽에서 23쪽으로 늘었다. 마지막 쪽이 거의 비는지 확인한다.
